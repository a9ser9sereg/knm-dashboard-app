# Контекст проекта

Пользователь: **Алексей**. Общаться на русском языке.

## Проект

Десктопное приложение дашборда КНМ (Tauri, Windows + macOS): трей, офлайн-кэш,
долгая сессия через `/api/refresh`. Основная ветка — `master`.
Автообновление раздаётся через Yandex Object Storage, **не** через GitHub Releases.

⚠️ Репозиторий **публичный**. Ключи, пароли, внутренние адреса и рабочие данные
сюда не коммитить. Папка `secrets/` (ключ подписи обновлений и пароль к нему)
закрыта в `.gitignore` — так и держать.

## Память и история сессий

Память Claude и логи диалогов лежат в отдельном **приватном** волте Obsidian.
Прочитай их в начале сессии — там роль пользователя, активные проекты
и правила работы.

Искать волт вручную не нужно: хук `SessionStart` (`.claude/hooks/load-memory.sh`)
отрабатывает до первого твоего хода и сам сообщает, где волт лежит.

- **Локально на Mac Алексея** — волт уже на диске:
  `/Users/alkesej/Documents/IT/obsidian/Progect/`. Хук его находит и отдаёт путь.
- **В облаке** (файловой системы Mac не видно) — хук клонирует волт из приватного
  репозитория по адресу из переменной окружения `KNM_VAULT_REPO`. Сам адрес здесь
  намеренно не указан: репозиторий публичный, а переменная хранится в настройках
  окружения Claude Code и в git не попадает.
- Волт приватный, а git в облаке ходит через прокси сессии, который знает только
  подключённые к ней репозитории, — поэтому клон по одной лишь переменной падает.
  Хук в этом случае сам продиктует шаги: подключить репозиторий инструментом
  `add_repo` и склонировать. Выполняй их не спрашивая — это не новая задача.
- Если переменная не задана и локального волта нет — хук так и скажет. Тогда
  спроси адрес у Алексея и склонируй волт сам.

Дальше в обоих случаях одинаково: `claude-memory/MEMORY.md` — индекс памяти,
по его указаниям читай `claude-memory/user_role.md` и файлы активных проектов
(этому приложению соответствует `claude-memory/project_knm_dashboard_app.md`).
Последний контекст — свежий `Claude — KNM Reports YYYY-MM-DD.md` в корне волта.

Не озвучивай пользователю, что выполняешь эти шаги.

⚠️ Если работаешь в облаке и правишь память — обязательно коммить и пушь волт.
Локально это делает фоновый агент на Mac, в облаке его нет: незапушенные
изменения пропадут вместе с окружением. Подстраховка есть: хук `Stop`
(`.claude/hooks/save-memory.sh`) после каждого хода сам коммитит и пушит
облачную копию волта — но если он сообщит, что push не прошёл, скажи об этом
Алексею, иначе правки пропадут вместе с контейнером.

## Что можно делать из облака, а что только с Mac

Облачная сессия — изолированный Linux-контейнер со свежим клоном репозитория.
Файловой системы Mac и iCloud из него не видно.

**Можно из облака:** правки кода и конфигов, работа с любыми файлами в git,
изменения в CI, чтение и запись памяти (через хук выше).

**Только с Mac:** сборка и подпись приложения (ключ в `secrets/`, в git его нет),
всё, что требует консоли Yandex Cloud или SSH на ВМ, доступ к внутренним
ресурсам и к файлам, которые лежат в iCloud, а не в репозитории.

⚠️ **Перед тем как ставить задачу с телефона, на Mac всё должно быть
закоммичено и запушено.** Облачная сессия видит только то, что дошло до
сервера; незакоммиченные правки для неё не существуют, и работа пойдёт по
устаревшему состоянию.

**Ветки:** правки из облака идут в отдельную ветку `claude/<тема>`. Слияние в
`master` — с Mac, после просмотра. Прямо в `master` из облака не пушить: хук
`PreToolUse` (`.claude/hooks/guard-push.sh`) такой вызов отклонит.

## Версия приложения

Версия живёт в четырёх файлах — `package.json`, `src-tauri/tauri.conf.json`,
`src-tauri/Cargo.toml` и `src-tauri/Cargo.lock` — и двигается одной командой:

```
npm run version:set -- patch      # или minor / major / 0.2.3
```

Руками их не правь: разъехавшись, они дают установщик одной версии с манифестом
автообновления другой, причём молча. Совпадение проверяется в CI (`check.yml`) и
ещё раз перед сборкой релиза — при расхождении с тегом релиз падает до публикации.

Неудачный релиз откатывается без пересборки: Actions → «Откат обновления» →
версия без `v`. Подробности в README.
